## Repo-local notes

- **LESSONS** — durable, *repo-specific* improvement notes (not cross-project — those go in the hub's `STATE.md`). Add an entry only when a lesson is likely to help a future session working in this repo specifically.
  - **2026-09-01 — The Mission Loop tables are empty in production.** `missions`, `mission_events`, and `evidence_snapshots` all had 0 rows in project `pkydkbuodikttfeawqsw` when the Strategic Delta was built, while the Foundry-layer tables (`actions` 8, `events` 11, `evidence_items` 4, `routed_requests` 4) had real data. Anything human-facing that predicts from mission state therefore renders its insufficient-context path until someone creates a Primary mission with a finish line. Check row counts before diagnosing a "broken" prediction — and design the empty path first, because it is the one that actually ships.
  - **2026-09-01 — Anonymous auth means demo state is per-browser.** `signInAnonymously()` scopes missions by `user_id` under RLS, so a fresh device or cleared browser is a *new* user with zero missions. A demo on an unfamiliar device starts empty by construction, not by failure.
  - **2026-09-01 — Local dev cannot sign in without `.env.local`.** `src/lib/supabase/client.ts` falls back to the literal string `your-anon-key-here`, which constructs a client successfully but 401s on every call. Console 401s plus "Sign-in failed" locally are expected, not a regression.
  - **2026-09-01 — supabase-js never throws; check `error` on every write.** `insert()`/`upsert()` resolve with `{ error }` on RLS or constraint failures, so `try/catch` around an awaited write silently swallows failed persistence. Two Delta write paths and one mission write had exactly this bug (UI flashed "saved" on rejected writes). Pattern: always `const { error } = await …insert(…); if (error) throw error`.
  - **2026-09-01 — Strategic Delta corrections use `mission_events` as a transitional persistence path, not as canonical ownership.** For the current vertical slice, `mission_events` is the smallest existing user-scoped append-only persistence path for corrections: `routed_requests` and `events` remain the canonical owners of routing/correction chains and generic audit history, but both are `workspace_id`-keyed Foundry tables (routing schema fields: `execution_lane`, `selected_agent`, `repository`) that the anonymous-auth front door cannot write without new plumbing. That is an ownership/schema **gap**, not a redefinition of `mission_events`. This choice does not make `mission_events` the canonical generic recommendation/correction authority; a future human-level correction authority will require explicit schema reconciliation.
  - **2026-09-01 — The Delta is the front door; chrome above it competes with the demonstration.** On a 375px screen, Operational badges, filter pills, and a Mission heading delayed the product moment. The shipping-first state is insufficient context — design that path as the instrument, not as an empty dashboard waiting for fixtures. Cognition belongs in a localized field whose colour encodes state; a card-wide spectrum gradient reads as generic AI chrome.
